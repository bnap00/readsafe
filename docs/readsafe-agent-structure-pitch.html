ReadSafe
Boundary MVP Contract

Pre-alpha design

Give agents the structure. Keep sensitive values out of their context.

ReadSafe is a planned open-source, local-first CLI that parses sensitive files on the developer machine and emits redacted structure metadata instead of raw values.

Planned interface 
$ readsafe inspect .env --json

{
  "schemaVersion": "0.1",
  "toolVersion": "0.1.0",
  "files": [{
    "path": ".env",
    "kind": "dotenv",
    "valueExposed": false
  }]
}

Security boundary

Local access, controlled output.

What ReadSafe does

ReadSafe reads and parses the file locally. It is designed to prevent raw values from appearing in agent-visible stdout, stderr, manifests, generated schemas, validation results, errors, or dry-run output.

What it does not do

ReadSafe is not a secret manager, sandbox, access-control system, or protection against an agent that bypasses the CLI. It cannot protect a value that was already included in a prompt, command argument, tool call, or log.

Initial wedge

Start with agent-safe dotenv operations.

Planned dotenv workflow

  • Inspect key names and broad types without returning values.
  • Add, update, remove, rename, and validate one key.
  • Return operation-level redacted dry runs.
  • Preserve formatting and write atomically.
  • Pass new values through stdin or a hidden prompt, not normal arguments.

Secondary capability

JSON and JSONL structure inference remains experimental. Safe schemas must omit value-derived examples, enums, constants, defaults, exact lengths, hashes, fingerprints, and inferred patterns that could disclose real data.

Agent contract

The output is the product.

Deterministic by default

  • Separate schemaVersion and toolVersion.
  • Stable path formatting and machine-readable errors.
  • No generation timestamp in canonical output.
  • Sampling and confidence metadata for inferred schemas.

Conservative agent instruction

Use ReadSafe for files known or suspected to contain private values. Do not force it for ordinary public JSON such as package.json, tsconfig.json, lockfiles, schemas, .env.example, or public fixtures unless repository policy marks them sensitive.

Installation commands are intentionally omitted until the corresponding Cargo, Homebrew, npm, container, or release artifacts actually exist.

ReadSafe — agents see the map, not the treasure.
